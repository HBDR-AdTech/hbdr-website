What each one changes, and the proof behind it

Nothing here gets built without your yes. Each idea names what it reads and writes, so you can judge the cost.

Stop the leaks
  • 01

    Fix the 55 broken HeaderBiddr ads.txt lines

    Send each of the 55 publishers the exact line with their own seller_id. Buyers that cross-check ads.txt against sellers.json can treat a mismatched line as unauthorized and skip the bid.

    Reads: publisher ads.txt filesWrites: nothing on our side

    Evidence: audit above; 33 lines point to another publisher's ID, 22 to IDs missing from sellers.json.

  • 02

    Retire inactive sellers from sellers.json

    85 publishers returned no readable ads.txt. Some will be gone. A seller that no longer sells should be retired, which the new /admin/supply page does without deleting history.

    Writes: sellers table (retired_at)

    Evidence: audit above; /admin/supply is being built on feat/supply-files.

  • 03

    Measure the lead funnel before changing it

    Count leads per month, split by contact form and support form, plus top referrers from Cloudflare Web Analytics. Every conversion idea below is judged against this number.

    Reads: contact_leads, one grouped count

    Blocked tonight: the Cloudflare connector was not connected, so I could not run it. The command for you is in HANDOFF-008.

  • 04

    Prove every "Available now" feature

    Name one live publisher for each of the ten features listed as available. CTV SSAI is listed before launch by your decision (D-033); this list is how we know when that changes. It also feeds the case studies in 13.

    Evidence: D-031, D-033; server/templates/components/features.ts.

Ship what buyers check
  • 05

    Ship Confiant or IAS through Prebid

    This answers your question on getting verification live faster. Confiant and IAS both have Prebid.js real-time data modules; DoubleVerify has none. The fastest path is a module in the wrapper's Prebid build, not custom code.

    1. Sign with one vendor and get its account ID.
    2. Add confiantRtdProvider or iasRtdProvider to the Prebid build in HBDR-prebid-wrapper.
    3. Turn it on for one publisher and compare revenue with an A/B split for a week.
    4. Roll it out and move the item to "Available now".

    Evidence: docs.prebid.org module pages (Confiant and IAS return 200; DoubleVerify 404), fetched 2026-10-24. hbdr-api/…/creative/quality/confiant.ts is a stub waiting on "vendor onboarding". The vendored prebid.js has neither module.

  • 10

    Switch the seller domain to hbdr.com

    Run hbdr.com/sellers.json beside headerbiddr.com/sellers.json, compare them, then redirect the old file and change the domain in publisher lines. Do 01 first, so publishers get one corrected line, not two changes.

    Evidence: D-031; doctrine 7 (build, run beside, delete).

  • 11

    Supply transparency page

    One public page with links to sellers.json and ads.txt, the lines a publisher adds, and the demand source count. It reads the same table as /sellers.json, so it cannot drift.

Turn visitors into qualified leads
  • 06

    "Email me this estimate" on the calculators

    The /tools calculators already ask for pageviews, CPM and fill. One button sends the visitor's inputs into the existing contact form, so the lead arrives with its numbers.

    Writes: contact_leads (existing table)
  • 07

    Waitlists for every "Coming soon" item

    Add a custom form field, "Interested in: ad verification / WordPress plugin", from /admin/form. No code change. It tells you which roadmap item has paying demand before you build it.

    Evidence: D-016 allows up to 20 custom fields from /admin/form.

  • 08

    Booking link for qualified leads

    When a lead reports 500,000+ monthly pageviews, the thank-you message shows your booking link. The link is an operator setting, not a constant.

    Evidence: D-027 minimum traffic; doctrine 14.

  • 09

    Free ads.txt checker on /tools

    A publisher enters a domain; the Worker fetches its ads.txt once and shows missing or wrong lines against HBDR's table. It is a lead magnet and the same tool fixes 01 at scale.

    Cost: one outbound fetch per checkRate limited per IP
  • 15

    Self-serve site revenue check

  • 16

    Evidence: ~/code/hbdr-suite/ECOSYSTEM.md:16 (Admin/Publisher/Referrer roles).
